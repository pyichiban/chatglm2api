# 泛化接口契约设计（Web LLM 渠道中立层）

> 目标：把本项目从「chatglm 专用客户端」泛化为「Web LLM 渠道通用框架」。
> 原则：**中立术语 + 最小原语集 + 能力协商**。不做过度抽象——共享逻辑下沉到基类，
> 各渠道只实现真正有差异的原语（预计 6~8 个）。
> 依据：`glm2api/` 现有实现 + `docs/PROTOCOL.md` + `docs/生图协议与实操.md`。

---

## 1. 现状契约盘点（glm2api 现有能力面）

### 1.1 凭据与会话生命周期

| 现有 API | 语义 |
|---|---|
| `Credential`（dataclass） | root_token（refresh）/ session_token（access）/ device_id / account_id / 反风控参数 |
| `load_credential()` | 从 env / 文件 / 整条 cookie 加载，JWT 解析补齐字段 |
| `ensure_token(force)` | session_token 过期则续期 |
| `refresh()` | 用 root_token 换新 session_token；**root_token 会轮换，必须原子落盘** |
| `save_credential()` | 原子写（tmp + os.replace），失败必须显式报错 |

### 1.2 操作面（6 组端点 → 9 个方法）

| 方法 | 上游语义 | 备注 |
|---|---|---|
| `user_info()` / `left_score()` | 账号资料 / 余额 | 余额单位「分」，渠道间完全不可比 |
| `models()` | 可用模型清单 | 无上下文长度/计费字段 |
| `list_conversations(page, size)` / `iter_conversations()` | 会话列表（页码翻页） | 按 update_time 降序 |
| `chat(assistant_id, message, conversation_id, stream, …)` | 对话（SSE） | 首轮 conversation_id=None → 服务端懒创建 |
| `create_conversation(msg)` | =「发首条消息取回 id」 | 上游**没有**创建端点，属派生方法 |
| `history(conversation_id, …)` | 历史消息（已实证） | `mainchat-api/conversation/messages`，升序全量、无分页 [2026-10-16] |
| `rename_conversation()` / `conversation_title()` | 改名 / 查标题 | |
| `delete_conversations(ids)` | 批量删除 | 单删也走 bulk |
| `stop_stream(mid)` / `update_status(mid)` | 中止生成 / 标记已读 | update_status 是清言特有语义 |
| `generate_image(msg, aspect_ratio, …)` | 生图 | 实证为「换 agent + cogview 参数的 chat」 |

### 1.3 两种流形态

- **透传**（`stream=True`）：上游 SSE 字节原样 yield，不解析、不改写、不补 [DONE]；
  截断时抛 `GlmStreamTruncated`。
- **聚合**（`stream=False`）：内部消费流，按段落归并后一次性返回 dict
  （`text / thinking / parts / finished / error / frames`）。
  聚合规则：`part.status=="init"` 是增量、`"finish"` 是该段全文（覆盖）。

### 1.4 渠道适配点（每接入一个新渠道都要重写的东西）

| 适配点 | chatglm 现状 | 是否渠道特有 |
|---|---|---|
| 签名算法 | `md5(ts-nonce-secret)` 三件套头 | ✅ 渠道特有 |
| 客户端指纹 | IDE/Electron UA + sec-ch-ua + X-Exp-Groups 等 | ✅ 渠道特有 |
| 动态风控参数 | `refer__991`（WEB 通道）/ 无（IDE 通道） | ✅ 渠道特有 |
| Cookie 策略 | jar 管理，业务 cookie 与 WAF cookie 分离 | ⭕ 半通用 |
| 瞬时拒绝 | 40012 + 指数退避 | ⭕ 通用机制，码值渠道特有 |
| SSE 帧语义 | init=delta / finish=全文 / 顶层 finish 收尾 | ⭕ 语义近似但字段名渠道特有 |
| 收尾判定 | 顶层 `status=="finish"`，无 [DONE] | ✅ 渠道特有 |

### 1.5 错误分类（已验证可用）

`GlmAuthError`（凭据失效，可自愈重试一次）/ `GlmRateLimitError` / `GlmTransientRejection`
（风控瞬时拒绝，退避可恢复）/ `GlmUpstreamError` / `GlmStreamTruncated`（流被截断，不得伪装收尾）。

## 3. 泛化架构：三层

```
┌─ Client（中立 API，渠道无关）────────────────────────────┐
│  chat / stream / iter_conversations / history / rename…  │  ← 调用方只看这层
├─ Channel（渠道适配，每渠道一个子类）──────────────────────┤
│  实现 6~8 个原语 + 声明 Capabilities                      │
├─ Transport（共享机制，基类实现）──────────────────────────┤
│  会话/续期/落盘 · 重试退避 · Cookie jar · 流消费/聚合 ·   │
│  错误归一化 · ChannelProfile(指纹+签名+反风控参数)        │
└───────────────────────────────────────────────────────┘
```

设计取舍（实用主义）：

1. **共享逻辑全部下沉基类**：翻页迭代、聚合、退避、续期落盘、错误归一——这些已被 chatglm
   实测打磨过，新渠道直接继承。
2. **渠道子类只写「端点映射 + 字段翻译 + 签名/指纹」**，预计 200~400 行/渠道。
3. **原样透传字段统一放 `raw`**：中立字段保证跨渠道可用，渠道特有信息不丢。
4. **能力协商**：不是所有渠道都有历史/改名/生图；用 `capabilities` 集合声明，
   未实现的能力调用时抛 `NotCapable`，而不是让子类写一堆 `raise NotImplementedError` 的空方法。

## 4. 核心数据契约（dataclass，语言中立）

```python
@dataclass
class SessionCredentials:
    root_token: str                     # 根凭据（可轮换，必须持久化）
    session_token: str = ""             # 会话令牌（可空，自动续期）
    device_id: str = ""                 # 设备标识（缺失时渠道自行生成并回填）
    account_id: str = ""                # 账号主键（可从 token 解析）
    anti_bot_tokens: dict[str, str] = field(default_factory=dict)  # 动态风控参数袋
    extra_cookies: dict[str, str] = field(default_factory=dict)
    source: str | None = None           # 持久化路径；None=不可落盘

@dataclass(frozen=True)
class Capabilities:                     # 能力协商（渠道子类声明）
    chat_stream_raw: bool = True        # 原样 SSE 透传
    history: bool = False               # 历史消息
    rename: bool = False
    delete: bool = False
    delete_bulk: bool = False
    stop_generation: bool = False       # 中止生成
    image_generation: bool = False
    credits: bool = False               # 余额查询
    lazy_conversation: bool = True      # 会话由首条消息懒创建（Web LLM 普遍如此）

@dataclass
class ModelInfo:
    id: str                             # 模型代号
    display_name: str = ""
    tags: list[str] = field(default_factory=list)
    reasoning_levels: list[str] = field(default_factory=list)   # 如 low/high/max
    raw: dict = field(default_factory=dict)                     # 渠道原样

@dataclass
class ConversationSummary:
    conversation_id: str
    agent_id: str = ""                  # 渠道的智能体身份（如 chatglm assistant_id）
    title: str = ""
    message_count: int | None = None    # 上游没有则 None
    updated_at: int | None = None       # Unix 秒
    raw: dict = field(default_factory=dict)

@dataclass
class ChatOptions:                      # 全部可选，渠道不支持的项忽略并记入 result.ignored
    model: str | None = None
    agent_id: str | None = None         # 缺省用渠道默认 agent
    conversation_id: str | None = None  # None=新会话（懒创建）
    mode: str | None = None             # 渠道自定义模式，值透传
    reasoning_effort: str | None = None # low/medium/high/max
    web_search: bool | None = None
    image_options: dict | None = None   # aspect_ratio/style/scene…（image_generation 渠道）
    extra: dict = field(default_factory=dict)                   # 渠道私有参数直通

@dataclass
class ChatResult:                       # 非流式聚合结果（跨渠道同构）
    conversation_id: str = ""
    message_id: str = ""                # 助手消息 id（中止/引用用）
    text: str = ""                      # 正文（生图渠道含 Markdown 图片）
    reasoning: str = ""                 # 思考过程
    images: list[str] = field(default_factory=list)             # 成品图直链
    finished: bool = False              # 上游正常收尾
    error: dict | None = None           # 上游报错对象（原样）
    ignored_options: list[str] = field(default_factory=list)
    raw: dict = field(default_factory=dict)                     # 渠道原样（parts 等）
```

**流式事件契约**（`stream=True` 的中立形态）：

```python
@dataclass
class ChatEvent:
    kind: str          # "text_delta" | "reasoning_delta" | "image" | "frame" | "done" | "error"
    text: str = ""     # delta 增量 或 image_url
    raw: bytes | dict | None = None    # frame=原始帧；error=错误对象
```

- `raw passthrough` 保留为渠道级方法（`chat_raw()`），**中立层只承诺事件流**。
  理由：透传字节对 OpenAI 兼容网关有用，但字节格式渠道间完全不可比。
- 收尾判定统一为「渠道适配器把上游收尾帧翻译成 `done` 事件」；传输层截断一律抛
  `StreamTruncated`，**任何渠道都不得伪造收尾事件**（R36 铁律，写进契约）。

## 5. Channel 抽象基类（每渠道必须实现的原语）

```python
class Channel(ABC):
    """Web LLM 渠道适配器。子类实现 8 个原语 + 声明能力；其余全部继承。"""

    name: str                       # 渠道名（"chatglm" / "traework" / …）
    capabilities: Capabilities

    # ── 必须实现 ─────────────────────────────────────────────
    @abstractmethod
    def build_profile(self) -> "ChannelProfile":
        """渠道档案：签名算法 + 客户端指纹头 + 默认端点基址。
        Transport 据此组装请求；指纹必须与该渠道真实客户端逐头对齐
        （chatglm 实测：头组合不一致会被 WAF 挂起/拒绝）。"""

    @abstractmethod
    def refresh_session(self, cred: SessionCredentials) -> SessionCredentials:
        """用 root_token 换新 session_token。实现方负责返回**轮换后的新 root_token**；
        落盘由 Transport 统一处理（原子写，失败必须报错）。"""

    @abstractmethod
    def send(self, op: str, payload: dict, *, stream: bool = False) -> Any:
        """签名 + 发请求 + 解渠道信封，返回**渠道原始 result**。
        op 为渠道内部操作名；信封错误在此翻译成统一异常（见 §6）。"""

    @abstractmethod
    def op_user_profile(self, session) -> dict: ...
    @abstractmethod
    def op_list_models(self, session) -> list[ModelInfo]: ...
    @abstractmethod
    def op_list_conversations(self, session, page: int, size: int) -> tuple[list[ConversationSummary], bool]:
        """返回 (本页会话, has_more)。"""

    @abstractmethod
    def op_chat(self, session, req: ChatOptions) -> Iterator[ChatEvent]:
        """发起对话并产出**归一化事件流**。必须把上游收尾翻译成 done 事件；
        上游报错翻译成 error 事件；传输截断抛 StreamTruncated。"""

    # ── 能力可选（capabilities 声明后才需实现）────────────────
    def op_history(self, session, conversation_id: str, limit: int) -> list[dict]: ...
    def op_rename(self, session, conversation_id: str, title: str) -> None: ...
    def op_delete(self, session, conversation_ids: list[str]) -> None: ...
    def op_stop(self, session, message_id: str) -> None: ...
    def op_credits(self, session) -> "Credits | None": ...
```

**Transport/基类提供的共享实现**（子类免写）：

| 方法 | 逻辑来源（chatglm 已验证） |
|---|---|
| `chat(req, stream=False)` | 消费 `op_chat` 事件流聚合为 `ChatResult` |
| `chat_stream(req)` | 产出 `ChatEvent` 迭代器；渠道的 `chat_raw()` 供字节级透传 |
| `iter_conversations(size)` | 自动翻页直到 has_more=False |
| `ensure_session()` | session_token 过期→refresh→**原子落盘**；401 自愈重试一次 |
| `_request_with_retry()` | 瞬时拒绝指数退避（基类持策略，渠道给码值判定器） |
| 错误归一化 | 渠道码值 → 统一异常（§6） |

## 6. 统一错误契约

| 中立异常 | 触发 | 调用方对策 |
|---|---|---|
| `AuthError` | 凭据失效（渠道码 40102/40103、HTTP 401 等） | 基类自动 refresh 重试一次；仍败则提示重新取凭据 |
| `RateLimitError` | 显式限流（HTTP 429 等） | 退避或降速 |
| `TransientRejection` | 风控/WAF 瞬时拒绝（chatglm 40012） | 基类自动指数退避；耗尽后抛出，可稍后重试 |
| `UpstreamError` | 其它业务错误 / 非 JSON（WAF 拦截页） | 按 message 排查 |
| `StreamTruncated` | 流在读到收尾帧前中断 | **必须当错误处理**；调用方可安全重试 |
| `NotCapable` | 调用了渠道未声明的能力 | 换渠道或降级 |

翻译规则：渠道子类在 `send()` 里只做「码值→异常类」的映射；重试、自愈、落盘全在基类。

## 7. 契约级硬规则（从 chatglm 实测上升为全渠道纪律）

1. **root_token 轮换必须原子落盘**，落盘失败显式报错（不落盘=账号失效）。
2. **流式请求不得设总超时**；收尾以「渠道收尾事件」为准，任何渠道不得补伪造收尾帧。
3. **流被截断必须抛 `StreamTruncated`**，不得伪装成正常结束。
4. **messages 只带当前一条**，多轮上下文靠 conversation_id（Web LLM 服务端普遍如此）。
5. **客户端指纹必须逐头对齐真实客户端**（chatglm 实测：头组合不一致 → WAF 挂起/40012）。
6. **会话懒创建**：不提供「创建会话」端点；`create_conversation()` 若提供，语义为
   「发首条消息并返回 conversation_id」。
7. **余额/积分只透传不换算**：各渠道单位与消耗规则不可比，中立层禁止建模。
8. **动态风控参数进 `anti_bot_tokens` 袋**：不解析、不猜测生成算法，由渠道适配器决定
   获取方式（抓包复制 / 独立通道豁免 / 逆向 JS）。

## 8. 迁移路径（不破坏现有调用方）

1. `glm2api/` 改造为 `channels/glm.py`（`GlmChannel(Channel)`），现有 `GlmClient` 变成
   `GlmChannel` 的薄别名层，**现有方法签名保持不变**。
2. `constants/sign/credential/sse/errors` 归入 `channels/glm/` 适配器内部，
   其中 `credential`、`errors`、`sse` 的骨架上移到中立层。
3. 新渠道接入 checklist：
   - 抓包 → 产出协议文档（端点/头/帧语义/收尾判定）
   - 实现 8 原语 + `Capabilities`
   - 用真实凭据跑通回归清单（参考本项目 §6 验收标准）
4. 回归测试范式沿用：**用抓包帧做离线回放测试**（`tests/test_offline.py` 模式），
   锁死帧语义，不发网络请求。
